# Egypt Nutrition Coach

تطبيق عربي لتخطيط الأكل والتمارين ومتابعة الوزن والنوم والاستشفاء. محركات التخطيط والمتابعة تعمل على الخادم بدون استدعاءات AI أثناء الاستخدام. الإصدار الحالي في `package.json`: **0.12.0**.

## التغذية والمتابعة

- خطط أكل إقليمية تراعي الهدف والميزانية والأطعمة المتاحة والاستبعادات والحالة الصحية المدعومة.
- تسجيل الوجبات المخططة بحصص مختلفة، والأصناف بالجرام، والوجبات اليدوية، مع **تأكيد صريح لإغلاق يوم الأكل**؛ تسجيل الوجبات أو بلوغ نسبة من السعرات لا يغلق اليوم تلقائيًا.
- بدائل وجبات تحت قيود النظام نفسه، وأرشيف إصدارات الخطط منفصل عن سجل الأكل الفعلي.
- رسائل منفصلة للتغذية والتدريب والعادات، تربط الملاحظة بالبيانات المسجلة وخطوة عملية قصيرة. تراعي نقص التسجيل وتاريخ البيانات والجاهزية والألم، مع تنويع يومي وثبات الرسالة لنفس البيانات أثناء اليوم.
- أهم الرسائل ظاهرة في ملخص قصير، والتفاصيل قابلة للتوسيع. معلومات عامة متنوعة عن التغذية والتمرين والمية والنوم والاستشفاء، مع زر لمعلومات إضافية.
- المتابعة آلية؛ لا تدّعي مراجعة بشرية، ولا تعتبر غياب التسجيل عدم التزام أو وجع العضلات دليلًا على النمو.

## التمرين وتسجيل الأداء

- مكتبة ٨٦٨ تمرينًا مع العضلات والمعدات والشرح الإنجليزي وبيانات المصدر والترخيص.
- تقسيمات الجسم كله، علوي/سفلي، دفع/سحب/أرجل، وعضلة في اليوم، حسب الأيام والوقت والمعدات والقيود الصحية المدعومة.
- تمارين وزن الجسم والمقاومة غير المقاسة بالكيلوجرام تُسجل بالعدات والمجموعات والمجهود **بدون خانة وزن أو عرض «٠ كجم» في كارت التمرين**. أجهزة المساعدة تعرض وزن المساعدة عند ملاءمته.
- الأوزان في واجهة التسجيل للعرض فقط؛ أزرار الزيادة والنقصان تتحرك بمقدار **٢٫٥ كجم** مع احترام حدود الحقل. لا توجد خانة يحدد فيها المستخدم مقدار الزيادة.
- اقتراح زيادة الحمل تلقائيًا له شروط مستقلة: أداء متكرر قابل للمقارنة، وعدات ومجهود مناسبين، واستشفاء يسمح بالزيادة. خطوة الأزرار وحدها لا تفرض زيادة تلقائية.
- بعد الحفظ يتحول التمرين إلى كارت مختصر بعلامة إتمام وملخص الأداء وزر **تعديل**. التمارين غير المسجلة تظل مفتوحة، وتُعرض ملاحظة الألم المسجل عند وجوده.
- إضافة وحذف الجولات، وحفظ مسودة العدات والأوزان والمجهود وعدد الجولات عند التنقل بين التبويبات. تعديل تسجيل اليوم يحدث السجل نفسه بدل إنشاء نسخة مكررة.
- تأكيد الجانبين للتمارين الأحادية، واحتساب الجلسة الجزئية أو المكتملة من المجموعات الفعلية. لا تُخترع مدة جلسة أو RPE عند غياب تسجيلهما.
- متابعة النوم والتعب والضغط والألم والمرض، مع مراجعة تخفيف الحمل أو السعرات أو حجم التدريب، واعتماد المستخدم للتعديلات المقترحة.
- مراجعة الـFull Body بعد ٨ أسابيع من أول جلسة مكتملة في البرنامج الحالي. الاقتراح يراعي الانتظام والاستشفاء والأيام المتاحة؛ مرور الوقت وحده لا يفرض تغيير التقسيمة. التفاصيل في [`split-review.mjs`](split-review.mjs).

## المحاكاة والموقع العادي

المحاكاة تستخدم محرك الأوامر نفسه الموجود في الموقع العادي، مع ساعة افتراضية وحساب تخزين منفصلين. يمكن البدء بشخصية تجريبية أو نسخة من بيانات المستخدم، ثم التسجيل يدويًا أو تعبئة يوم فارغ بسيناريو: انتظام، ثبات وزن، ضعف استشفاء، تمرين فائت، ضعف تسجيل غذائي، أو ألم.

حد الجولة ٩٠ يومًا. تتراكم السجلات وتتجدد خطة الأكل عند انتهاء أسبوعها في المحاكاة، وتنتج المراجعات من البيانات الفعلية داخل الجولة. التعبئة التجريبية لا تستبدل يومًا يحتوي على تسجيلات. يمكن الخروج والعودة لاستكمال الجولة؛ بدء جولة جديدة لا يعد بحذف أرشيف الجولات السابقة.

اختبارات [`tests/simulation-parity.test.mjs`](tests/simulation-parity.test.mjs) تقارن نتائج أوامر الموقع العادي والمحاكاة في حالات الجاهزية والتعب والألم، وتشمل اختبارات أخرى عزل السجلات والساعة ومنع انتقال بيانات المحاكاة للحساب الفعلي.

## التشغيل المحلي

يتطلب **Node.js 24 أو أحدث**. Python 3 مطلوب فقط عند إعادة استيراد مكتبة التمارين.

نفّذ الأوامر من مجلد المستودع:

```powershell
npm.cmd ci
npm.cmd run check
npm.cmd run dev
```

المعاينة المحلية: `http://127.0.0.1:8787`. اختبارات الخادم المحلي تستخدم هيدر `oai-authenticated-user-id` بهوية اختبار. مدخل Cloudflare العام يحذف الهيدر المرسل من العميل ويشتق الهوية من آلية المصادقة المعتمدة؛ هيدر الاختبار ليس وسيلة لتسجيل الدخول في الإنتاج. إعدادات المصادقة وعقود الموبايل في [دليل التكامل](docs/KMM_BACKEND_INTEGRATION.md) و[عقد API](contracts/openapi.yaml).

## الفحوص

أبقِ الخادم المحلي يعمل في نافذة منفصلة عند تشغيل فحوص المتصفح:

```powershell
npm.cmd run test:browser
node scripts/browser-exercise-load.mjs
node scripts/browser-messages.mjs
npm.cmd run audit:matrix
```

فحوص المتصفح الحالية تستخدم Microsoft Edge افتراضيًا؛ يمكن اختيار قناة مثبتة أخرى عبر `PLAYWRIGHT_CHANNEL`، مثل `chrome`.

آخر مراجعة للتحديث بتاريخ **٢٤ أكتوبر ٢٠٢٦**:

- نجاح **١٧٣ اختبارًا** في `npm run check`، بما يشمل الخادم وD1 والمتابعة والمحاكاة والتوافق مع السجلات القديمة.
- نجاح رحلات الأونبوردينج، والأكل، والتدريب، والمسودات وانقطاع الاتصال، والمحاكاة في المتصفح.
- نجاح فحص تمارين وزن الجسم والأوزان: الحفظ والتعديل وإعادة التحميل، إضافة وحذف الجولات، الكروت المختصرة، خطوة ٢٫٥ كجم، والتبديل.
- عدم وجود تمرير أفقي في فحص كروت التمرين على عرضي ٣٩٠ و١٠٢٤ بكسل.
- مصفوفة توليد: **٢٢٥٠ إعداد تمرين و٣٣٣ إعداد تغذية** بدون أخطاء في الفحوص. نجح توليد ٣٣٠ خطة تغذية؛ رُفضت ٣ إعدادات لعدم كفاية المكتبة لتحقيق القيود.

هذه نتائج السيناريوهات المختبرة، وليست ضمانًا لتغطية كل حالة صحية أو كل جهاز. نتائج المصفوفة المحلية تُكتب في `outputs/audit-matrix.json`.

## النشر

كل العمل والالتزامات والرفع مباشرة على `main`، والنشر على العامل وقاعدة البيانات المذكورين أعلاه فقط:

```powershell
git checkout main
git pull --ff-only origin main
npm.cmd run check
npm.cmd run deploy
git add -A
git commit -m "Describe the change"
git push origin main
```

عند وجود ترحيلات D1 جديدة، طبّقها على القاعدة المعتمدة قبل تشغيل الكود الذي يعتمد عليها:

```powershell
npm.cmd run deploy:d1
```

أوقف خادم المعاينة المحلي قبل إعادة البناء أو النشر على Windows إذا كان يمسك ملفات `dist/client`.

## المصدر والتراخيص

بيانات التمارين مشتقة من [OpenExerciseDB](https://github.com/rfivesix/OpenExerciseDB)، بترخيص CC BY-SA 4.0 مع الاحتفاظ بتراخيص ونسب السجلات الأصلية داخل `data/exercises.json`. النسخة المثبتة `202610112340`، بلا صور أو فيديو. الوصف وحالة الترجمة لا يمثلان مراجعة بشرية من فريق التطبيق.

```powershell
python scripts/import-exercises.py
```

يتوقف الاستيراد إذا اختلف SHA-256 المثبت؛ تحديث المصدر يحتاج مراجعة وإعادة تثبيت البصمة.
