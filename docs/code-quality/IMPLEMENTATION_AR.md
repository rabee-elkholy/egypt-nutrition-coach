## الإصلاحات الفعلية

- تنظيف موحد قابل للتكرار لمستمعات hashchange وplanner-leave وfocus وvisibilitychange ومؤقت التحديث ومستمع إرسال النماذج.
- إيقاف مؤقت الصفحة عند مغادرتها وتشغيل مؤقت واحد عند العودة. التخلص من الصفحة يوقف طلبات القراءة دون إلغاء الكتابة.
- رد القراءة الذي سبق حفظًا أو تبديل وضع أو إنهاء صفحة لا يستطيع استبدال الحالة الجديدة.
- العملية غير المؤكدة تبقى محفوظة على جلسة الصفحة بنفس الجسم والمفتاح ووضع المحاكاة عبر إعادة التركيب؛ لا يُستنتج فشل الحفظ من إلغاء قراءة.
- وصول نتيجة حفظ من تركيب سابق لا يمسح عملية أحدث ولا يعيد تعطيل الصفحة أو يزيل علامة انشغال العملية الجديدة. إعادة التركيب تزيل علامة انشغال التركيب القديم، وتعرض زر إعادة المحاولة مع شرح ظاهر. الاختبار يكرر الحالة برد ناجح وانقطاع شبكة على عرضي 390 و1280 بكسل، ويثبت أن إعادة المحاولة لا تكرر الحفظ.
- إعادة محاولة القراءة الأولى عند العودة إذا أُلغيت أثناء التنقل، بدل ترك الصفحة في حالة تحميل دائمة.
- حفظ تاريخ نموذج الاستشفاء صراحة مع مسودة مرتبطة باليوم، حتى لا ينتقل إدخال قديم إلى يوم جديد دون قصد. هذا يستخدم حقل date الموجود أصلًا في API.
- تحقق إعدادات الإشعارات كلها يسبق تغييرها، فلا يغير إدخال غير صالح بعض الحقول أو يمسح مراجعة سابقة. الدليل الفاشل قبل الإصلاح والناجح بعده محفوظان.

## القياس

يُحسب نفس ملخص الرسائل مرة واحدة للمستهلكين داخل عرض الحالة، مع مفتاح يضم هوية الحالة والمراجعة والتاريخ ووقت الخادم. لم نضف تخزينًا مؤقتًا مشتركًا بين حسابات أو طلبات الخادم. أُبدل فرز آخر تسجيل بمرور واحد يحافظ على قاعدة اختيار آخر عنصر عند التعادل.

قياس محلي لمرتين من تجهيز الرسائل لنفس الحالة، خمس تكرارات بمئة عينة لكل حجم وبترتيب متبادل. النتيجة هي وسيط زمن العينة بالمللي ثانية:

| 7 | 2.518 | 1.060 |
| 90 | 11.835 | 5.643 |

كل عينة اجتازت تطابق محتوى الرسائل وحجمها. القياس متزامن مع أعمال محلية أخرى ولا يثبت SLA أو سعة إنتاجية أو تحسن كل مسارات النظام. الأرقام الخام والمنهجية في performance.json، ولا توجد دعوى عن تحسين تكلفة تحميل D1 الكامل.

## بوابات التحقق

- npm run check: فحص أنواع تدريجي، تحقق البيانات، بناء، تدقيق عدم وجود دورات استيراد ووجود أصول النشر، مقارنة المرجع، ثم اختبارات المشروع.
- npm run test:fast / test:worker: مجموعتان معلنتان لا تستبدلان الفحص الكامل؛ تشغيل ملفات الاختبارات محدود بالتوازي لحماية ذاكرة بيئة الاختبار دون إسقاط حالات.
- npm run test:browser: الأونبوردينج والمتابعة والشبكة والمحاكاة والاتفاقات، وتوقيت الرسائل وأول أسبوع، واختبار دورة الصفحة الجديد.
- اختبار دورة الصفحة: 50 إعادة تركيب و50 مغادرة وعودة، ثبات عدد المستمعات، مؤقت واحد، حفظ المسودة وتنظيف قابل للتكرار.
- اختبار ملكية العملية المعلقة ضمن مجموعة المتصفح الرئيسية. أدلة فشل مسح العملية الأحدث وتعطيل زر إعادة المحاولة، ثم نجاح الحالات الأربع بعد الإصلاح محفوظة في pending-*.log.gz.
- فحص source/assets يثبت أن ملفات mjs الجديدة منسوخة في dist/client وأن الاعتمادات بلا دورة. بقيت الملفات في الجذر لتوافق البناء الحالي.

المرجع اجتاز 315 اختبارًا. الإصدار المرشح اجتاز 320 اختبارًا في الجولة المسجلة، وتبعتها جولة نهائية بعد تثبيت تاريخ نموذج الاستشفاء. سجلات الفشل والنجاح محفوظة مضغوطة بأسماء مستقلة. القياس الشامل 100 مستخدم × 90 يومًا قيد التسجيل في وقت كتابة هذه الفقرة؛ تقرير cohort-verification.json عند إصداره هو المرجع لنتيجته وليس هذا النص.

نجحت رحلتان مستقلتان عبر HTTP وD1 مدة كل منهما 365 يومًا: 730 يوم مستخدم، و3168 حدث HTTP، و2268 تحققًا دون فشل، و15 تعديل سعرات مقبولًا مع تغيير الهدف. النتائج التفصيلية في long-horizon.json؛ هذه مسارات محددة ولا تعني تغطية كل سيناريو ممكن.

## تدقيق الحفظ المستقل

تقرأ scripts/quality/verify-persistence.mjs قاعدة D1 والـWorker المحفوظين مع الرحلة، دون إعادة بناء مصدرهما أو تشغيل ترحيلات. تقارن السجلات المنظمة والخطط المؤرشفة بردود HTTP الأصلية. تستثني من وصفة التمرين ثلاثة حقول اقتراح لحظية معلنة فقط: suggestedKg وprogressionReason وsuggestionAt.

أظهر الإصدار الأول من أداة التدقيق 26 اختلافًا ظاهريًا على مجموعة من 13 مستخدمًا: كانت خطط الإنشاء الأولي مملوكة للحساب العادي، بينما بحثت الأداة عنها في مساحة المحاكاة. الإصلاح يحدد المالك من وضع كل طلب أصلي ويفحص المساحتين. لم تُحذف هذه الفحوصات. نجح التدقيق المصحح على 1625 سجلًا و228 خطة؛ ونقل مالك خطة عمدًا في نسخة قاعدة معزولة جعل الفحص يفشل كما ينبغي. السبب والاختبار السلبي في persistence-auditor-correction.json، ومصدر الأداة السابق وسجلات الفشل والنجاح محفوظة بجواره.

## التوافق والتسليم والرجوع

لا ترحيل قاعدة بيانات جديد ولا تغيير لعقد API أو قواعد التغذية/التمرين. تصدير/حذف الحساب وعزل المستأجرين والإيصالات ومنع التكرار و409 كلها ضمن الاختبارات القائمة. TypeScript اعتماد تطوير فقط؛ لم يتحول المشروع إلى TypeScript.

الرجوع بإعادة commit التغيير على main ثم بناء النسخة ونشرها على نفس Worker. لا يلزم عكس ترحيل D1 لهذا التغيير. قبل أي نشر فعلي يجب التحقق من حالة ترحيلات النسخة السابقة والنسخ الاحتياطي؛ نشر الواجهة القديمة وحدها لا يثبت توافق كل ترحيل سابق.

Cloudflare هو الهدف الوحيد. لا توجد صلاحية نشر متاحة في بيئة التنفيذ، لذلك لا تُعتبر اختبارات البناء أو المتصفح المحلي نشرًا حيًا. لم تُمس الاستضافة أو قاعدة الإنتاج، ولن يُنشأ بديل لهما.
