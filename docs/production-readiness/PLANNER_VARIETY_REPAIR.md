# Preserve compliant choices when variety preferences exhaust candidates

This source change follows c63009e. The completed d86f3a8 full-run archives remain unchanged, and are not retroactively current-source acceptance.

Original-seed diagnostics found another root cause: nonrepetition filters ran before the same strict sodium/carbohydrate checks. In user-006's failing dinner, the preferred subset contained one template while the unfiltered strict slot pool contained 51, including 43 within the unchanged slot sodium limit. Similar failures affected eight DASH profiles and a balanced profile with recorded hypertension. Variety preferences hid compliant options before the engine could consider them.

The planner now retains the eligible slot pool and ranks the preferred subset first. If that subset contains no nutrient-eligible candidate, it ranks the original strict pool through exactly the same fitting, sodium/carbohydrate filters and scores. Prepared-pool budget, region, diet, source bounds, medical exclusions and final daily validation remain intact. No estimated/missing sodium is converted to zero. This can repeat an allowed meal when the alternative is an incorrectly rejected plan; it does not broaden the user's allowed ingredients.
